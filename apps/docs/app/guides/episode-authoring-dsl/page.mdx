# Episode Authoring DSL

Tokovo episode code stays code-first.

Use the DSL for:

- device bootstrap
- app snapshots and explicit initial views
- timing
- camera
- audio
- per-app sequencing

For checked-in episodes, import the canonical builder:

```ts
import { episode } from "@tokovo/episodes/code-first-episode";
```

Typical shape:

```ts
const ep = episode("demo", { fps: 30, duration: "10s", title: "Demo" })
  .device("phone", "iphone16", { app: "app_whatsapp" })
  .snapshot("app_whatsapp", "phone", {
    conversations: [{ id: "dm_alex", name: "Alex", messages: [] }],
  })
  .view("app_whatsapp", "phone", {
    screen: "chat",
    conversationId: "dm_alex",
  })
  .whatsapp("phone", "dm_alex", (whatsapp) => {
    whatsapp.at("1s").receive("Alex", "Ready when you are.");
  });
```

`snapshot()` and `view()` are the only supported frame-0 app bootstrap APIs. Do not put app history into `device()` and do not rely on compiler-owned defaults.

## Built-in app tracks

The creator API exposes one named method per built-in app:

```ts
episode("multi-app", { fps: 30, duration: "12s" })
  .instagram("phone", (instagram) => {
    instagram.at("1s").navigate("home");
  })
  .linkedin("phone", (linkedin) => {
    linkedin.at("4s").navigate("messages");
  })
  .typewriter("desk", (typewriter) => {
    typewriter.span("6s", "10s").typeText("The ending writes itself.");
  });
```

The complete set is `whatsapp`, `imessage`, `instagram`, `x`, `linkedin`,
`snapchat`, `teams`, and `typewriter`. Use generic `track()` only while developing an
external app plugin; it is not the normal story-authoring surface.

## Device OS, lockscreen, and homescreen

Author OS appearance separately from app appearance. The OS value controls lockscreen,
homescreen, system chrome, notifications, and the default keyboard theme; the app keeps
ownership of its internal theme.

```ts
episode("system-demo", { fps: 30, duration: "12s" })
  .device("phone", "pixel", {
    app: "app_whatsapp",
    appearance: "light",
    locked: true,
    installedApps: ["app_whatsapp", "app_teams", "app_camera"],
    homeScreen: {
      pages: [["app_teams"]],
      dock: ["app_camera", "app_whatsapp"],
    },
    os: {
      locale: "ar-SA",
      appearance: "dark",
      hourCycle: "h24",
      time: new Date("2026-07-21T09:41:00Z"),
      dnd: true,
    },
  })
  .deviceTrack("phone", (device) => {
    device.at("2s").unlock();
    device.at("2.6s").goHome();
  });
```

Use `lockscreen.clock`, `lockscreen.controls`, `homescreen.grid`,
`homescreen.dock`, `homescreen.search`, or `homescreen.icon:<appId>` as camera targets.

## Screen recording and Dynamic Island presentation

Use the device track for the recording lifecycle. A new recording defaults to the iOS
three-second countdown and compact presentation. Expanding the island is a separate,
explicit presentation change; it does not restart capture. `hidden` dismisses the
indicator while capture continues, and stopping presents brief system feedback.

```ts
episode("recording-demo", { fps: 30, duration: "12s" })
  .device("phone", "iphone16", { app: "app_whatsapp" })
  .deviceTrack("phone", (device) => {
    device.at("1s").screenRecording(true, {
      presentation: "compact",
      microphoneEnabled: true,
      countdown: "3s",
    });
    device.at("5s").screenRecording(true, { presentation: "expanded" });
    device.at("7s").screenRecording(true, { presentation: "compact" });
    device.at("10s").screenRecording(false, { feedback: "2.4s" });
  });
```

Use `dynamicIsland` as the semantic camera target. Episode code should never guess the
island's pixel geometry or draw a duplicate overlay.

## Input sessions

The explicit input capability is field-scoped and random-access safe. It supports
grapheme-safe selection, replacement, IME composition, suggestions, RTL, and emoji.

```ts
episode("input-demo", { fps: 30, duration: "8s" })
  .device("phone", "iphone16", { app: "app_whatsapp" })
  .input("phone", "composer", {
    at: "1s",
    submitAt: "6s",
    locale: "ja-JP",
    script: [
      {
        type: "compose",
        updates: ["ashita", "あした", "明日"],
        commit: "明日送ります。",
      },
    ],
    expectedFinalValue: "明日送ります。",
    keyboard: { appearance: "dark", returnKey: "send" },
  });
```

## Notifications

Author semantic intent once. The notification capability resolves platform policy,
grouping, privacy, DND, foreground behavior, lifecycle, audio, and presentation.

```ts
episode("notification-demo", { fps: 30, duration: "10s" })
  .device("phone", "pixel", { app: "app_whatsapp" })
  .notificationTrack("phone", (notifications) => {
    notifications.at("1s").deliver({
      id: "release_reply",
      appId: "app_whatsapp",
      content: {
        title: "Release room",
        body: "Ready to ship?",
        avatar: { src: "/avatars/release-room.png", alt: "Release room" },
      },
      interruption: "timeSensitive",
      privacy: "private",
      threadId: "release_room",
      reply: {
        actionId: "reply",
        placeholder: "Reply",
        textPayloadKey: "text",
        target: {
          appEvent: {
            appId: "app_whatsapp",
            type: "MESSAGE_SENT",
            payload: { conversationId: "release_room" },
          },
        },
      },
    });
    notifications.at("3s").openCenter();
    notifications.at("5s").reply("release_reply", "Ship it.");
    notifications.at("5.2s").closeCenter();
  });
```

Interruption levels are `passive`, `active`, `timeSensitive`, and `critical`.
Preview policy is explicit (`always`, `whenUnlocked`, or `never`), and invalid app IDs,
actions, assets, or out-of-lifecycle interactions fail during preparation.

## Story language

Use scenes when the episode is a narrative rather than a systems showcase. Scene time is
local, so inserting or moving a scene does not require retiming every action inside it.

```ts
import { actor, cast, episode } from "@tokovo/episodes/code-first-episode";

const people = cast({
  me: actor("me", {
    name: "Me",
    identities: { x: { id: "x_me", handle: "studiolead" } },
  }),
  riya: actor("riya", {
    name: "Riya",
    avatar: "/avatars/riya.jpg",
    identities: {
      whatsapp: { name: "Riya G." },
      x: { id: "x_riya", handle: "riya" },
    },
  }),
});

episode("reveal", { fps: 30, duration: "20s" }).scene(
  "private message",
  { at: "4s", duration: "8s" },
  (scene) => {
    scene.conversation(
      {
        app: "whatsapp",
        deviceId: "phone",
        conversationId: "dm_riya",
        currentActor: people.me,
      },
      (chat) => {
        chat.open().wait("1s");
        const reveal = chat.receive(people.riya, "That someone is for you.", {
          hold: "2s",
        });
        chat.reply("Delete this from the universe.", reveal);
        scene.focus(reveal, { scale: 1.1 });
      },
    );
  },
);
```

`scene.at()` and `scene.wait()` move a scene-local cursor. Raw app, camera, audio,
overlay, and device tracks nested under a scene also interpret their `at()` and `span()`
times relative to the scene start.

### Consistent conversations

`scene.conversation()` provides the same `open`, `send`, `receive`, `reply`, `at`, and
`wait` verbs for WhatsApp, iMessage, Snapchat, Teams, Instagram DMs, LinkedIn messages,
and X messages. Use the named raw app method when an app-specific action is needed.

### Social posts and handles

`scene.social()` provides `post`, `comment`, `open`, `at`, and `wait` across Instagram,
LinkedIn, and X. `post`, `comment`, `send`, and `receive` return typed story handles.
Handles carry the stable device and semantic anchor target, so camera code does not need
to repeat app-specific anchor strings.

```ts
scene.social(
  { app: "x", deviceId: "phone", currentActor: people.me },
  (social) => {
    const post = social.post("The reveal is live.");
    social.wait("2s").comment(post, people.riya, "Finally.");
    scene.follow(post, "3s", { scale: 1.1 });
  },
);
```

### Automatic direction

`.director("ViralDramaV1")`, `.director("Cinematic")`, and
`.director("Documentary")` now compile real camera choreography. The director recognizes
message, DM, post, reply, typing, and notification events across built-in apps. Manual
camera tracks remain available for hero shots and multi-device composition.
