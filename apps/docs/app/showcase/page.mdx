## Camera VNext Flagship

The Camera VNext reel keeps one WhatsApp story immutable and swaps only its prepared camera plan.
Use the kinetic plan for the complete lens preview:

```bash
EPISODE_ID=whatsapp-cinematic-flagship \
CAMERA_PLAN_ID=kinetic \
pnpm --filter video-runner render:fast
```

Use `restrained` to compare the same story without the nonlinear lens treatment:

```bash
EPISODE_ID=whatsapp-cinematic-flagship \
CAMERA_PLAN_ID=restrained \
pnpm --filter video-runner render:fast
```

`render:fast` produces an explicitly labelled SVG reference preview for nonlinear optics. Final
quality still fails closed through the texture compositor:

```bash
EPISODE_ID=whatsapp-cinematic-flagship \
CAMERA_PLAN_ID=kinetic \
PROFILE=release \
pnpm render:episode
```

Render the complete system proof directly:

```bash
EPISODE_ID=os-surface-mega-exhaustive pnpm --filter video-runner render:fast
```

## Catalog Profiles

Use `release` for creator-facing episodes and `studio` for the full app/system showcase surface.

```bash
TOKOVO_EPISODE_CATALOG_PROFILE=studio pnpm --filter video-runner dev
```

## Quality Checklist

Before calling a showcase v1-ready:

- `pnpm validate` passes.
- The episode renders through `render:fast`.
- All referenced assets exist under `apps/video-runner/public`.
- Camera targets resolve to cinematic subjects instead of app fallback boxes.
- The final MP4 and manifest are kept out of git unless they are intentional docs assets.
