# @tokovo/renderer

The React and Remotion rendering layer for Tokovo.

## Responsibilities

- render devices and app surfaces from runtime state
- compute deterministic layouts
- render camera, overlays, and OS chrome layers
- host projected device-owned surfaces such as lockscreen, homescreen, notifications,
  Dynamic Island, and call overlays

Renderer should render through registries, not by hardcoding app behavior.

## Key Exports

- renderers: `TokovoRenderer`, `CinematicStageRenderer`, `AudioLayer`
- overlays: call and story overlays
- layout and engines: `computeLayout`, `computeLayoutEngine`, `useLayoutEngine`, `useAudioEngine`
- camera integration: `CameraProjectionPassRegistry`, `projectCinematicFrame`
- registry integration: `RendererRegistryProvider`

## Current Rule

System chrome must scale from device-aware metrics and editorial insets, not ad hoc render-pixel constants.
Lockscreen, homescreen, keyboard, and notification semantics stay in their owning device
packages; renderer composes their projections and supplies their cinematic subjects to the pure
camera evaluator before painting outputs.
